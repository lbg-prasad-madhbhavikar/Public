Metadata Service: Comprehensive Documentation
This document provides a step-by-step guide on how to set up, configure, and run the Metadata Service application. It also includes a detailed technical write-up covering High-Level Design (HLD) and Low-Level Design (LLD), explaining architectural decisions and component interactions, along with an Entity-Relationship Diagram (ERD).

1. How to Use This Code (Step-by-Step Guide)
Follow these steps to get the Metadata Service up and running.

1.1. Prerequisites
Before you begin, ensure you have the following installed:

Java Development Kit (JDK) 17 or higher:
Verify with: java --version
Gradle (Optional, but recommended): The project uses a Gradle wrapper (./gradlew), so direct Gradle installation isn't strictly necessary, but it helps for common commands.
Verify with: gradle --version
PostgreSQL Database: The application uses PostgreSQL as its primary data store.
Ensure you have a PostgreSQL server running and accessible.
You'll need credentials for a user with sufficient permissions to create schemas and tables.
Git (Optional): If cloning the repository.
1.2. Project Setup
Obtain the Code:
If the code is in a Git repository:
git clone <repository-url>
cd <project-directory>
If you have the files locally, ensure they are organized as a standard Spring Boot Gradle project (e.g., src/main/java, src/main/resources, build.gradle, etc.).
Database Creation:
Connect to your PostgreSQL server (e.g., using psql, pgAdmin, or DBeaver).
Create a new database for the application. For example:
CREATE DATABASE metadata_cache;
Make a note of the database name, username, and password, as you'll need them for configuration.
1.3. Configuration
The application's configuration is managed through src/main/resources/application.yaml. You need to externalize sensitive variables or environment-specific values.

Open src/main/resources/application.yaml:
Database Configuration: Update the spring.datasource section with your PostgreSQL details. It's configured to read from environment variables for production readiness, but you can hardcode values for local development if preferred.
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/metadata_cache}
    username: ${DB_USERNAME:postgres}
    password: ${DB_PASSWORD:password}
Local Dev Example (hardcoded):
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/metadata_cache
    username: postgres
    password: my_db_password
Production Example (via environment variables):
export DB_URL="jdbc:postgresql://your-prod-db:5432/metadata_cache_prod"
export DB_USERNAME="prod_user"
export DB_PASSWORD="prod_password"
./gradlew bootRun
Collibra API Client Configuration: Update the collibra section.
collibra:
  base-url: ${COLLIBRA_BASE_URL:http://localhost:8081} # Replace with your Collibra tenant URL
  username: ${COLLIBRA_USERNAME:your-collibra-user}    # Replace with your Collibra username
  password: ${COLLIBRA_PASSWORD:your-collibra-password} # Replace with your Collibra password
  source-id: ${COLLIBRA_SOURCE_ID:1}                   # Unique ID for Collibra in your 'core.source' table
Note: The source-id must match the source_id value for 'Collibra' in your core.source table (which is seeded with 1 by default via Liquibase).
Cache Retention: Adjust the metadata.cache.retention.days as needed.
metadata:
  cache:
    retention.days: ${METADATA_CACHE_RETENTION_DAYS:7} # Data considered fresh for X days
Retry Configuration: The retry.collibra section configures the retry logic for Collibra API calls.
retry:
  collibra:
    max-attempts: 3
    backoff-delay-ms: 1000
    backoff-multiplier: 2
Hibernate DDL (IMPORTANT): Ensure spring.jpa.hibernate.ddl-auto is set to none for production environments.
spring:
  jpa:
    hibernate:
      ddl-auto: none # IMPORTANT: Set to 'none' for production. Use 'update' ONLY for development.
1.4. Database Migration (Liquibase)
The project uses Liquibase for database schema management.

Open a terminal in the project's root directory.
Run the Liquibase update command:
./gradlew liquibaseUpdate
This command will apply the schema changes defined in src/main/resources/db/changelog/db.changelog-master.xml to your configured PostgreSQL database. It will create the core and landing schemas and their respective tables, along with seeding initial core.source and core.entity_type data.
1.5. Build and Run the Application
Build the Project:
./gradlew build
This compiles the Java code, runs tests, and packages the application into a JAR file.
Run the Application:
./gradlew bootRun
The application will start, typically on http://localhost:8080. You will see Spring Boot logs in your console.
1.6. Accessing the Application
OpenAPI Documentation (Swagger UI):
Once the application is running, open your web browser and navigate to:
http://localhost:8080/swagger-ui.html
This provides an interactive API documentation interface where you can explore and test the REST endpoints.
Test REST Endpoints:
Get all entities: GET http://localhost:8080/api/metadata/entities
Get entity by ID: GET http://localhost:8080/api/metadata/entities/{uuid} (You'll need a UUID from your database after a successful batch run).
Get entities by Source ID: GET http://localhost:8080/api/metadata/entities/by-source/{sourceId} (e.g., 1 for Collibra)
1.7. Running Tests
To run the JUnit test cases provided in the test files:

./gradlew test
This command will execute all unit and integration tests defined in src/test/java.

3. Technical Write-up: High-Level and Low-Level Design
3.1. High-Level Design (HLD)
The Metadata Service is designed as a standalone Spring Boot application responsible for ingesting, curating, caching, and serving metadata from various external sources. Its primary goal is to provide a unified, performant, and reliable access layer to metadata, abstracting away the complexities and specific APIs of different source systems.

Architectural Principles:

Abstraction: Decouple metadata ingestion logic from specific source systems.
Modularity: Clearly defined components with single responsibilities.
Resilience: Handle transient errors during external API calls.
Scalability: Use Spring Batch for robust, restartable data ingestion.
Maintainability: JPA for persistence, OpenAPI for API documentation.
Data Freshness: Explicit caching strategy with defined retention.
3.1.1. Key Components
REST API Layer (MetadataController): Exposes curated metadata entities via REST endpoints for consumption by other applications or users. Uses OpenAPI 3 for documentation.
Metadata Fetching Layer (MetadataFetcher & Implementations):
MetadataFetcher (Interface): Defines the contract for fetching data from any metadata source.
CollibraRestStrategy (Implementation): Concrete strategy for interacting with the Collibra API.
Data Ingestion & Curation (Spring Batch, JpaCoreUpsertService):
Spring Batch: Orchestrates the multi-step data ingestion process (fetch raw, upsert to core). Provides robustness, monitoring, and restartability.
JpaCoreUpsertService: Handles the transformation and persistence of raw data into the normalized core database schema. This service now includes logic to dynamically create missing entity types and upsert relations uniquely (updating existing ones rather than creating duplicates).
Scheduling & Refresh (MetadataRefreshService): Triggers the Spring Batch ingestion job periodically and manages data freshness by marking old data as stale.
Data Storage (PostgreSQL):
landing schema: Stores raw, unprocessed JSON payloads from external sources. Acts as a staging area.
core schema: Stores normalized, curated metadata entities, attributes, and relationships. This is the application's "cache" or "single source of truth" for served metadata.
External API Client (CollibraApiClient): A client library (mocked in the provided code) responsible for direct communication with the external metadata source's API. Test-specific static state for failure simulation has been removed from this production class.

3.2. Low-Level Design (LLD)
3.2.1. Core Concepts & Decision Choices
MetadataFetcher (Strategy Pattern):
Decision: Use a MetadataFetcher interface (fetchPage, persistRaw, upsertCore). This implements the Strategy Pattern, allowing easy integration of new metadata sources (e.g., Apache Atlas, Tableau) without modifying the core ingestion logic.
Benefit: High extensibility. Adding a new source simply requires creating a new MetadataFetcher implementation and its corresponding API client.
Two-Phase Data Persistence (Landing & Core Schemas):
Decision: Store raw JSON payloads in landing.raw_payload first, then transform and store curated data in core.entity, core.entity_attribute, core.entity_relation.
Benefit:
Auditability: Preserves the original raw data received from the source.
Resilience: If transformation fails, you can re-process the raw data.
Decoupling: Raw schema changes don't immediately impact the core schema.
landing.raw_payload acts as a short-term, raw data cache before curation.
Spring Batch for Ingestion:
Decision: Leverage Spring Batch for the data ingestion pipeline (fetchStep, mergeStep).
Benefit:
Robustness: Provides transactional processing, restartability (important for large datasets), and skip/retry logic.
Monitoring: Spring Batch's JobRepository tracks job executions, steps, and status, providing observability.
Scalability: Designed for high-volume, enterprise-grade batch processing.
JPA for Core Data Persistence (JpaCoreUpsertService):
Decision: Use Spring Data JPA with Hibernate for managing core.* entities.
Benefit:
Productivity: Reduces boilerplate code for CRUD operations.
Object-Relational Mapping (ORM): Maps Java objects to database tables, simplifying data manipulation.
Transactions: Spring's @Transactional annotation simplifies transaction management.
Enhanced Data Integrity: Now includes logic to create missing entity types on the fly and properly upsert relations (updating existing ones) to maintain data consistency.
Data Freshness / Caching (fetched_at, data_status, @Scheduled):
Decision: Instead of a traditional in-memory cache, the database itself acts as the persistent cache. Data freshness is managed by fetched_at timestamp on core.entity and a data_status field. A scheduled job periodically marks old data as "STALE".
Benefit:
Durability: Data persists across application restarts.
Consistency: All consumers see the same "cached" data.
Simple Freshness Policy: Easy to implement time-based cache invalidation (marking as stale).
Explicit Status: Allows distinguishing between "fresh" and "stale" data for consumers.
Spring Retry for External API Calls:
Decision: Use Spring Retry's @Retryable annotation on the fetchPage method in CollibraRestStrategy.
Benefit:
Resilience: Automatically retries transient network or API errors, making the ingestion more robust.
Configurable: Retry attempts and backoff strategies are externalized in application.yaml.
OpenAPI 3 (Springdoc) for REST Documentation:
Decision: Integrate springdoc-openapi-starter-webmvc-ui.
Benefit:
API Discoverability: Automatically generates interactive API documentation (Swagger UI).
Usability: Provides clear descriptions of endpoints, request/response structures, and error handling.
Developer Experience: Simplifies integration for consumers of the metadata service.
Centralized Error Handling (@ControllerAdvice):
Decision: Use @ControllerAdvice and @ExceptionHandler for global error handling in the REST layer.
Benefit:
Consistency: All API errors return a standardized ErrorResponse DTO.
Maintainability: Error handling logic is centralized, reducing duplication in controllers.
Improved UX: Provides clear, descriptive error messages to API consumers.

3.2.2.2. Sequence Diagram: Metadata Ingestion Job
This sequence diagram illustrates the flow of a single run of the Spring Batch ingestion job, triggered by the scheduler.

sequenceDiagram
    participant S as MetadataRefreshService (Scheduler)
    participant JL as Spring Batch JobLauncher
    participant J as metadataJob (Spring Batch)
    participant FS as fetchStep (Tasklet)
    participant CRS as CollibraRestStrategy
    participant CAC as CollibraApiClient
    participant RR as RawPayloadRepository
    participant MS as mergeStep (Tasklet)
    participant JUS as JpaCoreUpsertService
    participant ER as CoreEntityRepository
    participant AR as CoreAttributeRepository
    participant RELR as CoreRelationRepository
    participant ETR as CoreEntityTypeRepository
    participant DB as PostgreSQL DB

    S->>JL: triggerMetadataIngestionAndCleanup()
    JL->>J: run(metadataJob)
    J->>FS: start()
    loop Fetch Pages
        FS->>CRS: fetchPage(page, size)
        CRS->>CAC: getAssets().getAssets(page, size)
        alt API Call Success
            CAC->>CRS: AssetPage (JSON)
            CRS->>RR: save(RawPayloadEntity)
            RR->>DB: INSERT into landing.raw_payload
            DB-->>RR: OK
            CRS-->>FS: hasMorePages = true/false
        else API Call Failure (Retryable)
            CAC--xCRS: Exception (e.g., Network)
            CRS--xCRS: Retry attempts (configured by @Retryable)
            alt All Retries Fail
                CRS--xFS: MetadataFetchException
                FS--xJ: StepExecutionException (Job Fails)
                J--xJL: JobExecution (FAILED)
                JL--xS: Exception
                S->>S: Log Error
                break Loop ends
            end
        end
    end
    FS->>J: finished()
    J->>MS: start()
    MS->>JUS: upsertCore(sourceId, endpoint)
    JUS->>RR: findBySourceIdAndEndpointAndProcessedFalse()
    RR->>DB: SELECT from landing.raw_payload (where processed=false)
    DB-->>RR: List<RawPayloadEntity>
    RR-->>JUS: rawPayloads
    loop For each rawPayload
        JUS->>ER: findBySourceIdAndExternalKey()
        ER->>DB: SELECT from core.entity
        DB-->>ER: Optional<CoreEntity> (found/not found)
        ER-->>JUS: entityStatus
        JUS->>ETR: findBySourceIdAndName()
        ETR->>DB: SELECT from core.entity_type
        DB-->>ETR: Optional<CoreEntityType>
        ETR-->>JUS: entityType
        alt Entity Type Found
            ETR-->>JUS: existing CoreEntityType
        else Entity Type Not Found
            JUS->>ETR: save(new CoreEntityType)
            ETR->>DB: INSERT into core.entity_type
            DB-->>ETR: new CoreEntityType (with ID)
            ETR-->>JUS: newly created CoreEntityType
        end
        JUS->>ER: save(CoreEntity)
        ER->>DB: INSERT/UPDATE core.entity
        DB-->>ER: OK
        JUS->>AR: save(CoreAttribute)
        AR->>DB: INSERT/UPDATE core.entity_attribute
        DB-->>AR: OK
        JUS->>RELR: findBySourceIdAndFromEntityAndToEntityAndRelationType()
        RELR->>DB: SELECT from core.entity_relation
        DB-->>RELR: Optional<CoreRelation>
        alt Relation Exists
            RELR-->>JUS: existing CoreRelation
            JUS->>RELR: save(existing CoreRelation with updated fetched_at)
            RELR->>DB: UPDATE core.entity_relation
        else Relation Does Not Exist
            RELR-->>JUS: Optional<CoreRelation> (empty)
            JUS->>RELR: save(new CoreRelation)
            RELR->>DB: INSERT core.entity_relation
        end
        DB-->>RELR: OK
        JUS->>RR: save(rawPayload.setProcessed(true))
        RR->>DB: UPDATE landing.raw_payload
        DB-->>RR: OK
    end
    JUS-->>MS: OK
    MS->>J: finished()
    J->>JL: JobExecution (COMPLETED)
    JL->>S: OK
    S->>S: cleanupStaleData()
    S->>ER: markEntitiesAsStale(cutoffTime)
    ER->>DB: UPDATE core.entity SET data_status = 'STALE'
    DB-->>ER: Rows Updated
    ER-->>S: Count
    S->>S: Log Success

package com.example.metadata;

import com.fasterxml.jackson.databind.JsonNode;

/**
 * Strategy interface for pulling metadata from any source (Collibra, Atlas, etc.).
 * Defines a contract for fetching a page of data, persisting raw responses, and
 * merging (upserting) the data into the core schema.
 */
public interface MetadataFetcher {

    /**
     * Fetches a single page of results from the external metadata source.
     * This method is typically called repeatedly until all pages are fetched.
     *
     * @param page zero‐based page index
     * @param size number of items per page
     * @return true if there are more pages to fetch after this one, false otherwise.
     * @throws MetadataFetchException on network/authentication failures or issues with the external API.
     */
    boolean fetchPage(int page, int size) throws MetadataFetchException;

    /**
     * Persists a raw JSON page payload into the `landing.raw_payload` table.
     * This acts as a staging area for the unprocessed, original response from the external source.
     *
     * @param page JsonNode representing the entire page payload received from the source.
     * @throws MetadataPersistenceException on database write errors.
     */
    void persistRaw(JsonNode page) throws MetadataPersistenceException;

    /**
     * Merges any unprocessed raw payloads from the landing zone into the core metadata tables
     * (`core.entity`, `core.entity_attribute`, and `core.entity_relation`).
     * This operation should be idempotent: re-running it won’t duplicate data but
     * will update existing records if their source data has changed.
     *
     * @throws MetadataPersistenceException on database write errors during the upsert process.
     */
    void upsertCore() throws MetadataPersistenceException;
}

package com.example.metadata.batch;

import com.example.metadata.MetadataFetcher;
import lombok.RequiredArgsConstructor;
import org.springframework.batch.core.*;
import org.springframework.batch.core.configuration.annotation.*;
import org.springframework.batch.repeat.RepeatStatus;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * Defines a Spring Batch job for metadata ingestion.
 * This job consists of two main steps:
 * 1) fetchStep: Pages through an external metadata source (e.g., Collibra) and
 * persists the raw JSON responses into a landing table. This step includes retry logic.
 * 2) mergeStep: Merges the raw data from the landing table into the normalized
 * core tables (entities, attributes, relations).
 */
@Configuration
@EnableBatchProcessing // Enables Spring Batch features and configuration
@RequiredArgsConstructor // Lombok generates a constructor with final fields
public class BatchConfig {

    // Spring Batch factories for building jobs and steps
    private final JobBuilderFactory jobBuilderFactory;
    private final StepBuilderFactory stepBuilderFactory;

    // Injected MetadataFetcher implementation (e.g., CollibraRestStrategy)
    private final MetadataFetcher metadataFetcher;

    private static final int PAGE_SIZE = 500; // Number of items to fetch per page in a single API call

    /**
     * Defines the main metadata ingestion job.
     * The job executes sequentially: fetchStep -> mergeStep.
     *
     * @param listener The job completion listener for logging job lifecycle events.
     * @param fetchStep The step responsible for fetching raw data from the external source.
     * @param mergeStep The step responsible for merging data into core tables.
     * @return The configured Spring Batch Job.
     */
    @Bean
    public Job metadataJob(JobCompletionNotificationListener listener,
                           Step fetchStep,
                           Step mergeStep) {
        return jobBuilderFactory.get("metadataJob") // Unique name for the job
            .listener(listener) // Attach the job listener for start/end logging
            .start(fetchStep) // Define the first step in the job flow
            .next(mergeStep) // Define the next step to execute after fetchStep completes
            .build();
    }

    /**
     * Defines the fetch step of the metadata job.
     * This `Tasklet` repeatedly calls the `MetadataFetcher` to fetch pages from the external source
     * until there are no more pages to retrieve. The `metadataFetcher.fetchPage` method is
     * designed to handle retries for transient network issues.
     *
     * @return The configured Spring Batch Step.
     */
    @Bean
    public Step fetchStep() {
        return stepBuilderFactory.get("fetchStep") // Unique name for the step
            .tasklet((contribution, chunkContext) -> {
                int page = 0;
                boolean hasMore;
                do {
                    // Fetch a page of metadata using the injected MetadataFetcher.
                    // Retry logic is applied at the MetadataFetcher implementation level.
                    hasMore = metadataFetcher.fetchPage(page++, PAGE_SIZE);
                } while (hasMore); // Continue looping as long as the fetcher indicates more pages
                return RepeatStatus.FINISHED; // Indicate that the step has completed its work
            })
            .build();
    }

    /**
     * Defines the merge step of the metadata job.
     * This `Tasklet` calls the `MetadataFetcher` to upsert (merge/update)
     * the raw data from the landing zone into the normalized core tables.
     *
     * @return The configured Spring Batch Step.
     */
    @Bean
    public Step mergeStep() {
        return stepBuilderFactory.get("mergeStep") // Unique name for the step
            .tasklet((contribution, chunkContext) -> {
                metadataFetcher.upsertCore(); // Perform the core upsert operation
                return RepeatStatus.FINISHED; // Indicate that the step has completed its work
            })
            .build();
    }

    /**
     * Defines the job completion listener bean.
     *
     * @return An instance of {@link JobCompletionNotificationListener}.
     */
    @Bean
    public JobCompletionNotificationListener listener() {
        return new JobCompletionNotificationListener();
    }
}

import org.springframework.beans.factory.annotation.Value;
import org.springframework.retry.annotation.Backoff;
import org.springframework.retry.annotation.Recover;
import org.springframework.retry.annotation.Retryable;
import org.springframework.stereotype.Component;

/**
 * Fetches metadata from Collibra via its REST API and caches it in a Postgres database.
 * This strategy specifically uses the generated Collibra API client and delegates
 * the core data upsert logic to a JPA-based service.
 * <p>
 * This class also incorporates Spring Retry for resilient API calls to Collibra.
 * </p>
 */
@Component
@RequiredArgsConstructor // Lombok generates a constructor with final fields
@Slf4j // Lombok annotation for logging
public class CollibraRestStrategy implements MetadataFetcher {

    private final CollibraApiClient client; // Client to interact with Collibra API
    private final RawPayloadRepository rawRepo; // Repository for persisting raw payloads
    private final JpaCoreUpsertService upsertService; // Service for upserting into core tables
    private final ObjectMapper mapper; // Jackson ObjectMapper for JSON conversions

    private static final String ENDPOINT = "/assets"; // The API endpoint this strategy fetches from

    /**
     * Fetches one page of asset metadata from Collibra.
     * The raw JSON response is then persisted to the landing zone.
     * <p>
     * This method is annotated with `@Retryable` to automatically retry on `MetadataFetchException`.
     * The retry configuration (max attempts, backoff strategy) is externalized in `application.yaml`.
     * </p>
     *
     * @param page zero‐based page index
     * @param size items per page
     * @return true if more pages remain to be fetched from Collibra, false otherwise.
     * @throws MetadataFetchException if there's an unrecoverable error during the API call after all retries.
     */
    @Retryable(
        value = MetadataFetchException.class, // Retry only on MetadataFetchException
        maxAttemptsExpression = "${retry.collibra.max-attempts}", // Max attempts from properties
        backoff = @Backoff(delayExpression = "${retry.collibra.backoff-delay-ms}", multiplierExpression = "${retry.collibra.backoff-multiplier}") // Exponential backoff
    )
    @Override
    public boolean fetchPage(int page, int size) throws MetadataFetchException {
        log.info("Attempting to fetch page {} (size {}) from Collibra API. Current attempt.", page, size);
        try {
            // Call the auto-generated Collibra client to get assets
            AssetPage assetPage = client.getAssets()
                                        .getAssets(page, size); // The mock CollibraApiClient now directly returns data
            // Persist the raw JSON response of this page to the landing table
            persistRaw(mapper.valueToTree(assetPage));
            log.info("Successfully fetched and persisted page {} from Collibra.", page);
            // Determine if there are more pages based on total pages reported by Collibra
            return assetPage.getTotalPages() > page + 1;
        } catch (Exception e) {
            // Wrap any exceptions in a custom MetadataFetchException to trigger retry
            log.warn("Failed to fetch page {} from Collibra: {}. Retrying...", page, e.getMessage());
            throw new MetadataFetchException(
                "Failed to fetch page " + page + " from Collibra", e);
        }
    }

    /**
     * Recovery method for `fetchPage` when all retries have been exhausted.
     * This method will be called if `fetchPage` fails after its maximum number of retries.
     * It allows for custom handling of the final failure (e.g., logging, alerting, fallback).
     *
     * @param e The last `MetadataFetchException` that occurred.
     * @param page The original page number attempted.
     * @param size The original page size attempted.
     * @return false, indicating that no more pages can be fetched due to persistent failure.
     * @throws MetadataFetchException Re-throws the exception to propagate the ultimate failure.
     */
    @Recover
    public boolean recoverFetchPage(MetadataFetchException e, int page, int size) {
        log.error("All retry attempts failed for fetching page {} from Collibra. Error: {}", page, e.getMessage());
        // Re-throw the exception to indicate the job step failed, allowing Spring Batch to handle the job status.
        throw e;
    }


    /**
     * Saves the raw JSON API response into the `landing.raw_payload` table.
     * This acts as a staging area for the data as it comes from the source.
     *
     * @param page JsonNode representing the raw page payload.
     * @throws MetadataPersistenceException if there's an error during database persistence.
     */
    @Override
    public void persistRaw(JsonNode page) throws MetadataPersistenceException {
        try {
            // Build a RawPayloadEntity from the received JSON page
            RawPayloadEntity entity = RawPayloadEntity.builder()
                .sourceId(client.getConfig().getSourceId()) // Get source ID from client config
                .endpoint(ENDPOINT) // Set the endpoint that was fetched
                .payload(page) // Store the raw JSON payload
                .processed(false) // Mark as unprocessed initially
                .build();
            rawRepo.save(entity); // Save the entity to the database
        } catch (Exception e) {
            // Wrap any exceptions in a custom MetadataPersistenceException
            throw new MetadataPersistenceException("Error persisting raw payload", e);
        }
    }

    /**
     * Merges unprocessed raw payloads from `landing.raw_payload` into the
     * `core.entity`, `core.entity_attribute`, and `core.entity_relation` tables.
     * This method delegates the actual upsert logic to `JpaCoreUpsertService`
     * and marks the processed rows in the landing table.
     *
     * @throws MetadataPersistenceException if there's an error during the upsert process.
     */
    @Override
    public void upsertCore() throws MetadataPersistenceException {
        try {
            // Delegate the core upsert logic to the JpaCoreUpsertService,
            // passing the source ID and endpoint to filter relevant raw payloads.
            upsertService.upsertCore(
                client.getConfig().getSourceId(),
                ENDPOINT
            );
        } catch (Exception e) {
            // Wrap any exceptions in a custom MetadataPersistenceException
            throw new MetadataPersistenceException("Error upserting core tables", e);
        }
    }

     * This involves fetching related data like attributes and entity type names to
     * present a more complete view of the entity to the API consumer.
     *
     * @param entity The {@link CoreEntity} object to convert.
     * @return An {@link EntityDto} representing the curated view of the entity.
     * @throws ResourceNotFoundException if the associated entity type is not found (should ideally not happen with proper data integrity)
     */
    private EntityDto convertToDto(CoreEntity entity) {
        // Fetch attributes for the given entity ID and collect them into a Map.
        Map<String, String> attributes = attributeRepo.findByEntityId(entity.getId()).stream()
            .collect(Collectors.toMap(CoreAttribute::getKey, CoreAttribute::getValue));

        // Fetch the entity type name using the entityTypeId.
        // If the entity type is not found (which indicates a data integrity issue if FKs are enforced),
        // a ResourceNotFoundException is thrown.
        String entityTypeName = entityTypeRepo.findById(entity.getEntityTypeId())
                                             .map(et -> et.getName())
                                             .orElseThrow(() -> new ResourceNotFoundException(
                                                 "Entity type with ID " + entity.getEntityTypeId() + " not found for entity " + entity.getId()));

        // Build and return the EntityDto.
        return EntityDto.builder()
            .id(entity.getId())
            .name(entity.getName())
            .externalKey(entity.getExternalKey())
            .type(entityTypeName) // Set the resolved type name
            .status(entity.getStatus())
            .lastSeen(entity.getLastSeen())
            .fetchedAt(entity.getFetchedAt())
            .dataStatus(entity.getDataStatus()) // Include the custom dataStatus
            .attributes(attributes) // Set the fetched attributes

package com.example.metadata.service;

import com.example.metadata.MetadataPersistenceException;
import com.example.metadata.core.CoreAttribute;
import com.example.metadata.core.CoreAttributeRepository;

import com.example.metadata.core.CoreEntityRepository;

import com.example.metadata.core.CoreEntityTypeRepository;
import com.example.metadata.core.CoreRelation;
import com.example.metadata.core.CoreRelationRepository;
import com.example.metadata.landing.RawPayloadEntity;
import com.example.metadata.landing.RawPayloadRepository;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Instant;
import java.util.Iterator;
import java.util.List;
import java.util.Optional;
import java.util.UUID;

/**
 * Service responsible for upserting (inserting or updating) raw metadata payloads
 * from the `landing.raw_payload` table into the normalized `core.*` tables
 * (entity, attribute, relation) using Spring Data JPA.
 * <p>
 * This service ensures data consistency by operating within a transaction.
 * It also handles the mapping of raw JSON fields to structured JPA entities.
 * </p>
 */
@Service
@RequiredArgsConstructor // Lombok generates a constructor with final fields
@Slf4j // Lombok for logging
public class JpaCoreUpsertService {

    private final RawPayloadRepository rawRepo; // Repository for raw payloads
    private final CoreEntityRepository entityRepo; // Repository for core entities
    private final CoreAttributeRepository attrRepo; // Repository for core attributes
    private final CoreRelationRepository relRepo; // Repository for core relations
    private final CoreEntityTypeRepository entityTypeRepo; // Repository for entity types
    private final ObjectMapper mapper; // Jackson ObjectMapper for JSON processing

    /**
     * Performs the upsert operation: processing raw payloads and merging them
     * into the core metadata tables. This method is transactional to ensure
     * data consistency. Each raw payload is processed, its data is transformed
     * into core entities, attributes, and relations, and then the raw payload
     * is marked as processed.
     *
     * @param sourceId The ID of the metadata source (e.g., Collibra's source ID).
     * @param endpoint The API endpoint that the raw data corresponds to (e.g., "/assets").
     * @throws MetadataPersistenceException if any database operation fails.
     */
    @Transactional // Ensures the entire method runs within a single database transaction
    public void upsertCore(int sourceId, String endpoint) {
        // Retrieve all unprocessed raw payloads for the given source and endpoint.
        List<RawPayloadEntity> pages = rawRepo
            .findBySourceIdAndEndpointAndProcessedFalse(sourceId, endpoint);

        if (pages.isEmpty()) {
            log.info("No unprocessed raw payloads found for sourceId {} and endpoint {}. Skipping upsert.", sourceId, endpoint);
            return;
        }

        log.info("Starting upsert for {} raw payload pages from sourceId {} and endpoint {}.", pages.size(), sourceId, endpoint);

        for (RawPayloadEntity rp : pages) {
            JsonNode results = rp.getPayload().get("results"); // Get the 'results' array from the JSON payload

            if (results == null || !results.isArray()) {
                log.warn("Payload for rawId {} does not contain a 'results' array or it's not an array. Skipping this raw payload.", rp.getRawId());
                rp.setProcessed(true); // Mark as processed to avoid re-attempting a malformed payload
                rawRepo.save(rp);
                continue;
            }

            for (JsonNode elem : results) { // Iterate through each element (e.g., asset) in the results array
                String extKey = elem.get("id") != null && !elem.get("id").isNull() ? elem.get("id").asText() : null;
                if (extKey == null) {
                    log.warn("Element in rawId {} payload has no valid 'id'. Skipping this element.", rp.getRawId());
                    continue; // Skip element if no external key is found
                }

                // --- 1. Upsert CoreEntity ---
                UUID entityId;
                Optional<CoreEntity> existingEntity = entityRepo.findBySourceIdAndExternalKey(sourceId, extKey);

                if (existingEntity.isPresent()) {
                    entityId = existingEntity.get().getId();
                    log.debug("Updating existing entity with ID: {} (External Key: {})", entityId, extKey);
                } else {
                    entityId = UUID.randomUUID(); // Generate a new UUID for a new entity
                    log.debug("Creating new entity with ID: {} (External Key: {})", entityId, extKey);
                }

                // Look up entity type ID by name. If not found, create it dynamically.
                String entityTypeName = Optional.ofNullable(elem.get("type"))
                                                .map(typeNode -> typeNode.get("name"))
                                                .filter(JsonNode::isTextual)
                                                .map(JsonNode::asText)
                                                .orElse("Unknown"); // Default type name if not present or invalid

                Integer entityTypeId = entityTypeRepo.findBySourceIdAndName(sourceId, entityTypeName)
                                                     .map(CoreEntityType::getEntityTypeId)
                                                     .orElseGet(() -> {
                                                         // Dynamically create new entity type if it doesn't exist
                                                         log.info("Creating new entity type '{}' for sourceId {}.", entityTypeName, sourceId);
                                                         CoreEntityType newEntityType = CoreEntityType.builder()
                                                                 .sourceId(sourceId)
                                                                 .name(entityTypeName)
                                                                 .description("Auto-created type from metadata source")
                                                                 .createdAt(Instant.now())
                                                                 .updatedAt(Instant.now())
                                                                 .build();
                                                         CoreEntityType savedEntityType = entityTypeRepo.save(newEntityType);
                                                         return savedEntityType.getEntityTypeId();
                                                     });


                CoreEntity entity = CoreEntity.builder()
                    .id(entityId)
                    .sourceId(sourceId)
                    .entityTypeId(entityTypeId)
                    .externalKey(extKey)
                    .name(elem.get("name") != null && !elem.get("name").isNull() ? elem.get("name").asText(null) : null)
                    .status(elem.get("status") != null && !elem.get("status").isNull() ? elem.get("status").asText(null) : null)
                    .lastSeen(elem.get("lastModifiedAt") != null && !elem.get("lastModifiedAt").isNull() ? Instant.parse(elem.get("lastModifiedAt").asText()) : Instant.now())
                    .fetchedAt(Instant.now()) // Update fetched_at every time it's successfully processed
                    .createdAt(existingEntity.isPresent() ? existingEntity.get().getCreatedAt() : Instant.now()) // Preserve original creation date
                    .updatedAt(Instant.now()) // Update record update timestamp
                    .dataStatus("ACTIVE") // Mark as active when processed
                    .build();
                entityRepo.save(entity); // Saves (inserts or updates) the entity

                // --- 2. Upsert Attributes ---
                JsonNode attrs = elem.get("attributes");
                if (attrs != null && attrs.isObject()) {
                    for (Iterator<String> it = attrs.fieldNames(); it.hasNext(); ) {
                        String key = it.next();
                        JsonNode valueNode = attrs.get(key);
                        String val = valueNode != null && !valueNode.isNull() ? valueNode.asText(null) : null;

                        CoreAttribute attr = CoreAttribute.builder()
                            .entityId(entityId)
                            .key(key)
                            .value(val)
                            .fetchedAt(Instant.now())
                            .build();
                        attrRepo.save(attr); // Saves (inserts or updates) the attribute
                    }
                }

                // --- 3. Upsert Relations ---
                JsonNode rels = elem.get("relations");
                if (rels != null && rels.isArray()) {
                    for (JsonNode rel : rels) {
                        String targetId = rel.get("targetId") != null && !rel.get("targetId").isNull() ? rel.get("targetId").asText() : null;
                        String relationType = rel.get("type") != null && !rel.get("type").isNull() ? rel.get("type").asText() : "UNKNOWN";

                        if (targetId == null) {
                            log.warn("Relation in rawId {} payload for entity {} has no valid 'targetId'. Skipping this relation.", rp.getRawId(), extKey);
                            continue;
                        }

                        try {
                            UUID toEntityId = UUID.fromString(targetId);
                            CoreRelation cr;
                            // Check if a similar relation already exists to upsert it
                            Optional<CoreRelation> existingRelation = relRepo.findBySourceIdAndFromEntityAndToEntityAndRelationType(
                                    sourceId, entityId, toEntityId, relationType);

                            if (existingRelation.isPresent()) {
                                cr = existingRelation.get();
                                log.debug("Updating existing relation with ID: {} between {} and {} of type {}", cr.getId(), entityId, toEntityId, relationType);
                            } else {
                                cr = CoreRelation.builder()
                                        .id(UUID.randomUUID()) // Generate new UUID for new relation
                                        .sourceId(sourceId)
                                        .fromEntity(entityId)
                                        .toEntity(toEntityId)
                                        .relationType(relationType)
                                        .build();
                                log.debug("Creating new relation with ID: {} between {} and {} of type {}", cr.getId(), entityId, toEntityId, relationType);
                            }
                            cr.setFetchedAt(Instant.now()); // Always update fetchedAt
                            relRepo.save(cr); // Saves (inserts or updates) the relation
                        } catch (IllegalArgumentException e) {
                            log.warn("Invalid UUID format for targetId '{}' in rawId {} payload for entity {}. Skipping relation. Error: {}", targetId, rp.getRawId(), extKey, e.getMessage());
                        }
                    }
                }
            }
            // Mark raw payload as processed after all its elements are handled successfully.
            rp.setProcessed(true);
            rawRepo.save(rp);
            log.debug("Raw payload with ID {} marked as processed.", rp.getRawId());
        }
        log.info("Finished upserting raw payload pages for sourceId {} and endpoint {}.", sourceId, endpoint);
    }
}

package com.example.metadata.service;

import com.example.metadata.core.CoreEntityRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.batch.core.Job;
import org.springframework.batch.core.JobParameters;
import org.springframework.batch.core.JobParametersBuilder;
import org.springframework.batch.core.launch.JobLauncher;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Instant;
import java.time.temporal.ChronoUnit;

/**
 * Service responsible for orchestrating the periodic refreshing and cleanup
 * of metadata. It uses Spring's scheduling capabilities to trigger a Spring Batch job
 * for data ingestion from external sources and then performs a cleanup of stale data
 * based on a configured retention period.
 */
@Service
@RequiredArgsConstructor // Lombok: Generates a constructor with final fields
@Slf4j // Lombok annotation for logging
public class MetadataRefreshService {

    private final JobLauncher jobLauncher; // Spring Batch JobLauncher to run jobs
    private final Job metadataJob; // The Spring Batch Job to be executed for ingestion
    private final CoreEntityRepository coreEntityRepository; // Repository for managing core entities

    // Configurable property for how many days to retain cached data as 'ACTIVE'.
    // Value is injected from application.yaml, with a default of 7 days.
    @Value("${metadata.cache.retention.days:7}")
    private int cacheRetentionDays;

    /**
     * Schedules the metadata ingestion and cleanup job to run periodically.
     * This method is configured to run daily at 2:00 AM using a cron expression.
     * <p>
     * The `cron` expression "0 0 2 * * ?" means:
     * <ul>
     * <li>Second: 0</li>
     * <li>Minute: 0</li>
     * <li>Hour: 2 (2 AM)</li>
     * <li>Day of Month: * (any)</li>
     * <li>Month: * (any)</li>
     * <li>Day of Week: ? (no specific day of week, allowing any day of month)</li>
     * </ul>
     * </p>
     * This job triggers the data fetching and upsert process, followed by a data cleanup.
     */
    @Scheduled(cron = "0 0 2 * * ?") // Runs every day at 2 AM
    public void triggerMetadataIngestionAndCleanup() {
        log.info("Triggering metadata ingestion and cleanup job...");
        try {
            // Build unique job parameters to ensure a new job instance is created for each run.
            // Using current timestamp makes parameters unique, preventing Spring Batch from complaining
            // about restarting an already completed job with the same parameters.
            JobParameters jobParameters = new JobParametersBuilder()
                .addString("jobId", String.valueOf(System.currentTimeMillis()))
                .toJobParameters();

            // Run the Spring Batch metadata ingestion job.
            jobLauncher.run(metadataJob, jobParameters);
            log.info("Metadata ingestion job completed successfully. Proceeding with cleanup.");

            // After ingestion, perform the cleanup of stale data.
            cleanupStaleData();

        } catch (Exception e) {
            // Log any errors that occur during job execution or cleanup.
            log.error("Error running metadata ingestion job or cleanup: {}", e.getMessage(), e);
        }
    }

    /**
     * Cleans up stale data from the `core.entity` table.
     * Entities whose `fetchedAt` timestamp is older than `cacheRetentionDays`
     * will be marked with a `dataStatus` of 'STALE'. This is a soft-deletion approach,
     * which keeps historical data accessible but flags it as not actively fresh.
     * The `@Transactional` annotation ensures that the database update is atomic.
     */
    @Transactional // Ensures the database operation is committed or rolled back as a single unit
    public void cleanupStaleData() {
        log.info("Starting cleanup of stale metadata. Retention period configured for: {} days.", cacheRetentionDays);

        // Calculate the cutoff time. Entities fetched before this instant will be marked stale.
        Instant cutoffTime = Instant.now().minus(cacheRetentionDays, ChronoUnit.DAYS);

        // Call the repository method to mark entities as stale.
        // This updates the 'dataStatus' column for entities older than the cutoff.
        int updatedCount = coreEntityRepository.markEntitiesAsStale(cutoffTime);
        log.info("Marked {} entities as stale (fetched before {}).", updatedCount, cutoffTime);
    }
}
